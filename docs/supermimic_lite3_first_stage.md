## 上游实际实现了什么

上游 `go2_supermimic/supermimic/train.py:360-409,474-495,499-541,570-587` 的循环有三个阶段：

1. **Collect**：真实 mjlab 仿真中用当前 Actor（也可让现有行为策略驱动部分环境）及探索噪声采样，把状态、动作、历史、环境信息及结束标志存入经验池。
2. **Fit World Model**：从经验池采样连续 k 步窗口；世界模型从初始真实状态开始自回归预测，再逐步与真实轨迹比较。模型将 `(状态, 当前动作, 上一动作, 随机化上下文, 地形扫描)` 映射到 `(下一状态, 平面位姿增量)`；使用输入及输出增量的运行统计归一化。参见 `world_model.py:53-97`。
3. **Improve Policy**：从经验池选真实起点，Actor 在世界模型中产生 H 步可微想象轨迹，计算奖励、软终止和存活权重；Actor 更新时冻结世界模型参数但保留计算图，通过 BPTT 反向传播到 Actor。Critic 使用想象轨迹的 TD(λ) 目标训练，并为 rollout 末尾提供价值估计。参见 `imagine.py:213-234,256-292`、`train.py:499-541`。

这不是“PPO 加预测辅助损失”。上游 `buffer.py:67-76` 对 `done` 做累积 mask，终止转移及之后的步骤不参与模型拟合，避免将重置后的新状态当作上一回合的下一状态；`train.py:435-472` 使用接触变化、腾空、跌倒相关窗口做优先采样和罕见事件归档。

上游适用对象是 mjlab Go2 的追球与躲避任务。其 70 维物理状态、关节顺序、传感器、追球奖励、软终止和控制器均不能原封不动用于 Lite3；上游并没有自动支持当前 Lite3 的所有奖励和随机扰动。原项目 `state.py:29-48` 定义 70 维状态、4 维上下文和 FR/FL/RR/RL 顺序；高度扫描是 `target/terrain.py:24-29` 的 77 点。迁移必须按本工程重新定义，并验证对应关系。

上游 `driver.py:42-79` 的行为策略依赖特定 Go2 TorchScript 的内部字段、默认姿势及分量历史排布，不能直接把它用于已有 Lite3 Student。其 `state.py:262-270` 历史按特征分块；Lite3 原训练的历史为时间帧排列，这两种展开顺序不可混用。

## Lite3 已核实的接口和约束

- `legged_gym/envs/go2/go2_config.py:32-39` 定义单帧 45 维观测、12 动作，特权观测在 `go2_env.py:23-47` 由速度、状态、接触力、力矩、加速度和 187 点地形扫描构成，共 263 维。Actor 顺序是：机身角速度 3、投影重力 3、速度指令 3、关节角偏差 12、关节速度 12、上一步动作 12。计算须保留现有缩放、噪声及裁剪。
- `rsl_rl/rsl_rl/runners/on_policy_runner_cts.py:97-98,153-157` 使用 `[环境数, 5, 45]` 历史：旧帧向前移动，末尾放新帧，done 环境清零后放入重置观测。网络实际展开顺序及执行时机必须逐项与现有实现对照，不以维数相同代替验证。
- `lite3_config.py:17-50` 配置四腿默认角 `(0,-1,1.8)`、Kd=0.7、安全限幅；Kp=20、action_scale=0.25、decimation=4 从 `go2_config.py:77-85` 继承，仿真步长 `legged_robot_config.py:240-241` 为 0.005 秒，策略周期 0.02 秒。关节应按运行时 URDF 名称映射，不能把配置字典的书写顺序当成仿真保证。
- `lite3_config.py:93-105,107-160` 覆盖平地和上下楼梯比例及速度课程，flat 及 rough flat 的实际生成见 `legged_gym/utils/terrain.py`；上/下楼命令的偏航角速度上限为零。课程、命令重采样及地形等级要复用既有实际行为，而不是为新算法静默更改。
- 真正碰撞终止和时间截断参见 `legged_robot.py:174-181`；`post_physics_step` 先算奖励，再重置已结束环境，之后计算并返回观测（`legged_robot.py:128-140`）。因此 `env.step()` 返回的 done 环境观测是在重置后组装的，不能误存为旧回合终态；而部分缓存（如机身角速度和投影重力）在 reset 前计算、在组装前未见重新计算，也不能未经验证就断言它是完整一致的新回合状态。收集器须在 reset 前捕捉需要的终态，或明确屏蔽不可得的终止转移；对 time-limit 与真实失败分别记录并选择正确的 bootstrap 语义。任何 hook 或新环境子类都应独立隔离并验证，不直接改现有共享实现。

## 已有 75k Student 与导出接口

75k Student 的原始文件和部署工程应保持原样。历史单帧和显式历史接口不能混为一谈：已有旧 75k TorchScript 输入为单帧 `[1,45]`，内部维护历史；现有部署 ONNX 输入为 `obs [1,45]` 和 `history [1,5,45]`，输出 `actions` 和 `next_history`，详见 `/mnt/A/hust_hbc/mai/lite3/lite3_student_deploy/INTERFACE_AUDIT.md`。本次新 Actor 的目标单输入 `[B,5,45] → [B,12]` 是新接口；若要接入现有部署，还须提供和测试显式转换/适配器，不能声称两者天然相同。

第一阶段 CPU 实测旧 75k TorchScript：batch=1 可运行 `[1,45] → [1,12]`，batch=2 尺寸不匹配；部署 ONNX 的两个输入和两个输出也都是固定 batch=1。若用于大量环境采样，需要研究从原 checkpoint 重建批量网络并证明与现有策略等价，不能直接将现有 batch=1 文件用于批推理。

下一阶段先检查 checkpoint 对应网络、历史、归一化和批量推理，再考虑把 Student **仅作为采集行为策略**；Teacher、Student、未来的 SuperMimic Actor、Critic、世界模型各司其职。不默认将 Student 权重加载到不同网络。只有在观测、参数、结构和动作处理经过验证后，才讨论 warm-start。

## 数据与算法迁移方案（待实现）

### 物理状态与转移

先从 Isaac Gym 原始状态制定带版本的 Lite3 字段表，明确维度、单位、机身/世界/航向坐标系、四腿及关节索引、归一化。候选包括机身相对地面高度、姿态/投影重力、线角速度、12 关节位置及速度、足端位姿/速度和接触、平面位置及 yaw。所需髋膝刚体字段和确切维度需按 Lite3 URDF 与运行时张量验证，**目前不宣称已确定总维数**。

一条转移应包括当前状态、位姿、已裁剪或实际执行动作及前序动作、45 维观测及 5 帧历史、命令及其重采样计时器、地形特权信息、环境随机化参数、奖励及各分量、终止/截断标志、reset 前下一状态和该状态可用标志。额外记录训练课程进度、地形种类、扰动时刻，防止重放使用当前环境参数代替采样当时的参数。

### 地形与随机化

`legged_robot.py:1208-1231` 的地形高度采样取离散格的最小值；上游 `target/terrain.py:38-58` 用双线性插值，前向数值和梯度都不同。应先做真实扫描的数值一致性基准，再单独研究可微替代，对楼梯边沿误差和梯度作定量报告。Actor 仍只接收 45 维，地形扫描可以给世界模型/训练期 Critic 使用。

`go2_config.py:41-75` 含摩擦、质量、质心、恢复系数、PD、电机零偏和强度随机化，以及 push 和动作延迟；`legged_robot.py:67-79` 在每个控制周期的不同仿真子步切换新旧动作。固定参数应按其实际变化周期存储于上下文；延迟需要保存足够的动作/执行过程信息。Push 是突发扰动，应记录事件和实际生效量或明确用随机扰动模型；不能声称由未观测输入的确定性世界模型准确预测。上游 `env/env_cfg.py:119` 甚至删除了 push，所以不可宣称其已解决此问题。独立无 push 试验可以用于排查，但最终对比必须写明配置差异，且不改变原训练任务。

### 奖励与终止

以 `lite3_config.py:75-92` 及其 `go2_config.py:155-195` 父类最终生效配置为准，建立逐项映射表，逐条核实权重、符号、dt、课程、何时采样和是否依赖前一状态。不要只抄贴在 Lite3 子类内的项目；例如 `hip_to_default` 从父类继承。高度奖励使用扫描点估计的相对地面高度（`legged_robot.py:1391-1406`），不是简单的世界坐标 z；动作平滑依赖当前和前两步动作（`legged_robot.py:1380-1382`）。高度与垂向速度项还有继承的课程倍率（`go2_config.py:160-162`）。

对于碰撞力、接触、硬阈值、终止等：需要先确定模型能否从状态预测相应物理量；可微近似须列出公式、权重及偏差，不能伪装成与真实奖励完全一致。将记录的真实状态逐项送入真实奖励和想象奖励，比较均值、最大误差及边界情况。软终止/生存概率应对齐实际终止与 time-limit 含义，并单独评估偏差。

### 训练阶段

按上游顺序构建独立代码：

1. 收集可复现、带版本的数据；使用小环境数验证时间对齐、接触、地形及 reset；如 Student 满足接口则用于部分数据采集。
2. 实现连续窗口回放、done/有效性 mask、罕见接触和跌倒附近窗口的采样；用真实样本拟合状态和位姿增量的多步自回归模型，保存归一化统计与模型。
3. 在冻结世界模型参数但保持输入梯度的前提下进行 imagine，重建原来的观测与历史、处理命令、计算可微奖励和生存权重；通过 BPTT 更新 Actor，用 TD(λ) 训练 Critic。要独立验证 Actor 梯度非零、世界模型参数未更新，不能把整个 rollout 放在 `torch.no_grad()` 里。
4. 新训练入口、日志、checkpoints、导出目录与旧项目隔离。新 ONNX 与旧部署间用明确的适配器；先离线测试，不真机执行。
